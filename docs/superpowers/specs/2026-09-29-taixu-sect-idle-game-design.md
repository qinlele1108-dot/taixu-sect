# 《太玄宗：掌门录》Windows 本地挂机游戏设计稿

日期：2026-09-29  
状态：平台方案修订，待用户审阅  
定位：可直接安装运行的 2D 修仙宗门经营挂机游戏原型

## 1. 产品目标

玩家以掌门身份经营一座修仙宗门，通过建筑生产、弟子排班、炼丹、秘境远征和境界突破形成持续成长循环。游戏面向 Windows 10/11，以独立桌面窗口运行，不依赖浏览器或网络服务，并通过本地存档支持在线与离线挂机。

首版追求完整且可反复游玩的单机循环，不包含账号、付费、多人、排行榜或复杂剧情。

## 2. 体验原则

1. **经营优先**：首屏是“掌门案牍”管理面板，信息密度高于战斗画面。
2. **反馈明确**：生产、升级、掉落、突破和离线收益都有即时数字、动效与音画反馈。
3. **长期成长**：十个大境界、四个小阶段、丰富物品和品相差异构成长线。
4. **低操作负担**：资源自动产出，远征自动进行；玩家的主要决策是排班、投入与取舍。
5. **原创表达**：参考成熟挂机游戏的循环结构，不复用现有游戏的角色、图标、文案或世界观资产。

## 3. 核心循环

建设宗门 → 安排弟子 → 获取资源 → 炼丹与炼器 → 派遣秘境远征 → 获得装备、功法和材料 → 培养弟子与提升宗门 → 突破境界 → 解锁更高阶内容。

在线状态每秒结算资源与任务进度；离线状态按离开时间计算，最多结算 8 小时。返回时先展示收益总览，再允许玩家逐项查看稀有掉落。

## 4. 主要系统

### 4.1 宗门建筑

首版包含五座可升级建筑：

- **太虚殿**：决定宗门等级、弟子上限和其他建筑等级上限。
- **灵田**：生产药材，并提高高品药材出现概率。
- **丹房**：将药材炼成丹药，可设置自动炼制队列。
- **灵矿**：生产矿材与灵石，提供炼器材料。
- **藏经阁**：保存功法，为弟子提供修炼效率与突破加成。

升级消耗灵石和对应材料。每座建筑显示当前产速、排班弟子、升级收益、耗时和解锁条件。

### 4.2 弟子与排班

初始提供三名原创弟子，分别偏向剑修、丹修和符修。弟子拥有境界、修为、根骨、悟性、气运和专长。

弟子可被安排到建筑、闭关位或远征队。岗位与专长匹配时获得效率加成；同一弟子在同一时间只能执行一个长期任务。玩家可为弟子装备武器、防具、法宝和功法。

### 4.3 十大境界

境界顺序固定为：

1. 炼气
2. 筑基
3. 金丹
4. 元婴
5. 化神
6. 炼虚
7. 合体
8. 大乘
9. 渡劫
10. 真仙

每个大境界包含初期、中期、后期、圆满四个阶段。小阶段依靠修为自动推进；跨越大境界需要修为达到上限，并消耗指定突破丹药与资源。突破有成功率，失败不降低境界，但会消耗部分材料并进入短暂调息。渡劫和真仙突破拥有独立视觉演出。

### 4.4 资源与物品

基础资源为灵石、药材、矿材、修为和气运。可收集物品约 80 种，分为：

- 武器
- 防具
- 法宝
- 功法
- 丹药
- 药材
- 矿材
- 秘境奇物

物品品相从低到高为：凡品、良品、上品、极品、玄品、地品、天品、仙品。品相决定基础倍率、词条数量、掉落光效和分解产物。同名装备允许出现不同品相和随机词条。

背包支持按类型、品相与可装备状态筛选。装备可穿戴、锁定和分解；材料可用于炼丹、炼器、建筑升级或境界突破。物品数据使用配置表维护，便于增加内容而不改动核心逻辑。

### 4.5 炼丹与炼器

丹房提供聚气丹、筑基丹等配方。配方消耗药材并占用炼制队列，弟子专长影响耗时和高品结果概率。

首版炼器以“强化与重铸”为主：消耗矿材强化装备，或重置随机词条。分解装备返回与品相对应的精炼材料。

### 4.6 秘境远征

玩家选择 1–3 名弟子组成远征队，进入按境界分层的秘境。远征自动推进并显示时间轴事件，包括战斗、采集、奇遇、受伤和宝箱。

队伍战力决定基础成功率，功法、职业组合和气运影响事件结果。失败只损失部分时间与耐力，不永久失去弟子或装备。每次远征结束后集中结算战利品。

## 5. 界面与美术

### 5.1 主界面

采用已确认的 C 方案“掌门案牍”：

- 顶部显示宗门等级、灵石、气运和挂机产速。
- 左侧为弟子排班列表与状态。
- 右上为今日产出和待处理宗务。
- 右下为炼丹、秘境和突破进度。
- 底部导航为总览、排班、库存、功法、远征。

首屏直接提供可操作内容，不设置营销式欢迎页。

### 5.2 视觉风格

采用已确认的“天青水墨”：青瓷色、淡墨纹理、深青文字和少量鎏金高光。界面以半透明宣纸面板、细描边、柔和阴影和墨迹过渡构成。稀有品相通过边框、微光、粒子和印章纹样区分，不仅依赖颜色。

界面以 1920×1080 为美术基准，最低支持 1280×720；窗口可缩放并支持全屏。正文默认不小于 16px，常用标签不小于 14px，在小窗口下通过页签和折叠面板保持清晰，不出现控件重叠。

### 5.3 动效与音效

- 资源增长使用轻量数字滚动与墨滴扩散。
- 建筑升级使用水墨晕染与印章落款。
- 稀有掉落使用品相色微光和粒子，不连续闪烁。
- 境界突破使用全屏雷云、剑光与书法境界字演出，并提供跳过按钮。
- 音效默认开启，可分别调节主音量、环境音与效果音，也可一键静音。

## 6. 技术方案

### 6.1 交付形式

使用 Godot 4.x 制作 2D Windows 桌面客户端，以独立 `.exe` 和资源包交付。游戏启动后直接进入主界面，不打开浏览器，不要求安装服务器或登录账号。首版完全离线运行。

项目以 GDScript 编写；界面使用 Godot `Control` 节点与主题资源，过场和数值反馈使用 Tween、AnimationPlayer、粒子和着色器。目标渲染器优先选择兼容模式，以覆盖常见集成显卡。

### 6.2 模块边界

- **配置资源**：境界、建筑、弟子、物品、配方和秘境数据，采用 JSON 或 Godot Resource。
- **模拟引擎**：Autoload 单例统一处理时间推进、生产、修炼、任务和离线结算。
- **库存系统**：物品实例、品相、词条、装备与分解。
- **存档系统**：版本化序列化、自动保存、导出、导入与重置。
- **场景层**：启动场景、掌门案牍主场景、库存、弟子、炼丹、远征和突破演出场景。
- **表现层**：主题资源、音频总线、粒子、着色器、动画和反馈。

界面只通过明确动作调用游戏状态，不直接修改配置表。模拟引擎接受经过限制的时间差，避免离线结算异常。

### 6.3 存档与异常处理

使用 Godot `user://` 目录保存版本化 JSON 存档，并保留一个自动备份。关键动作后立即保存，常规状态每 10 秒自动保存，在窗口关闭请求时先完成保存。设置与存档分开保存，方便重置游戏时保留音量和显示偏好。

- 存档解析失败：保留损坏副本，加载安全默认存档并提示用户。
- 系统时间倒退：离线收益按 0 计算。
- 超长离线：最多按 8 小时结算。
- 资源计算溢出：所有资源限制在安全上限并采用紧凑数字显示。
- 配置缺失：跳过无效物品并记录可见的非阻断提示，不使整局存档失效。

### 6.4 本地运行与发布

- 首版发布目标为 Windows 10/11 x64。
- 同时提供可直接启动的开发构建和正式导出构建。
- 游戏仅在自身存档目录写入数据，不修改注册表或系统设置。
- 支持窗口化、无边框全屏、音量调节、退出确认和存档导出。
- 若开发机未安装 Godot，实施阶段使用官方便携版编辑器与导出模板，不改变系统级配置。

## 7. 内容规模

首版目标内容：

- 10 个大境界、40 个小阶段
- 5 座建筑及其升级曲线
- 3 名初始弟子
- 约 80 种基础物品，支持 8 个品相与随机词条组合
- 6 个炼丹配方
- 8 个秘境层级与不少于 20 种事件
- 1 套完整离线收益、突破与存档流程

## 8. 验收标准

1. 新玩家可在一分钟内完成首次排班、建筑升级或远征操作。
2. 资源、排班、炼丹、远征、装备和突破构成闭环，无需重启游戏或手工修改数据。
3. 关闭并重新启动游戏后存档恢复正确，模拟离线后返回能够获得不超过 8 小时的离线收益。
4. 十个境界均可通过配置驱动推进，品相与随机词条能正确影响装备属性和视觉展示。
5. 1280×720 至 1920×1080 下界面不重叠、不裁切，鼠标和常用键盘操作有效。
6. Windows 导出版本可在未安装 Godot 的环境中启动；无阻断级脚本错误，关键流程经过手工试玩验证。

## 9. 参考边界

市场参考仅用于理解挂机收益、自动战斗和长期成长循环。视觉、名称、角色、图标、文本和数值均采用原创设计。参考资料包括 AFK Journey 官方介绍、Melvor Idle 离线机制说明与 Legend of Mushroom 商店页玩法描述。
