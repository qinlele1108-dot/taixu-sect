# 《太玄宗：掌门录》实施计划

日期：2026-09-29  
依据：`docs/superpowers/specs/2026-09-29-taixu-sect-idle-game-design.md`  
目标：交付可在 Windows 10/11 x64 独立运行的 Godot 2D 本地游戏原型

## 实施原则

- 先完成可反复游玩的最小闭环，再扩充十境界与物品内容。
- 游戏规则与界面分离；境界、物品、建筑和秘境均由配置驱动。
- 每个阶段都保持工程可启动，避免最后集中集成。
- 关键数值逻辑通过无界面测试脚本验证，表现层通过实际窗口试玩验证。
- 美术资产全部原创；生成资产进入项目后再统一调色、裁切和压缩。

## 阶段 1：Godot 工具链与项目骨架

1. 从 Godot 官方来源确认并获取当前稳定版 Windows 便携编辑器及导出模板。
2. 创建 `game/` Godot 工程，使用兼容渲染器，设计分辨率为 1920×1080，最低窗口为 1280×720。
3. 建立目录：
   - `game/scenes/`
   - `game/scripts/core/`
   - `game/scripts/ui/`
   - `game/data/`
   - `game/assets/art/`
   - `game/assets/audio/`
   - `game/tests/`
4. 配置 Autoload：`GameState`、`Simulation`、`SaveManager`、`AudioManager`。
5. 创建启动场景与掌门案牍空壳，确认窗口化启动、退出和无脚本错误。

验收：工程可从编辑器与命令行启动；空壳场景在 1280×720 和 1920×1080 下可见。

## 阶段 2：配置数据与基础模型

1. 定义资源、弟子、建筑、境界、物品、配方和秘境的数据结构。
2. 建立十境界、四十阶段及突破需求配置。
3. 建立八种品相的属性倍率、词条数量、掉落权重和视觉标识。
4. 先录入一组可玩的纵向切片：三名弟子、五座建筑、十二种物品、两个配方、两个秘境。
5. 编写配置加载和完整性检查，发现重复 ID、缺失引用或非法数值时给出明确错误。

验收：测试脚本可加载全部配置并打印结构化统计；故意放入错误数据时检查器能定位问题。

## 阶段 3：挂机模拟与数值循环

1. 实现统一时间推进：资源生产、弟子修炼、建筑升级、炼丹队列和远征计时。
2. 实现弟子岗位分配与专长加成。
3. 实现建筑等级、升级成本、产速和解锁条件。
4. 实现小阶段自动推进与大境界突破条件。
5. 实现数值上限与紧凑格式化显示。

验收：同一初始状态推进相同秒数得到一致结果；岗位切换会正确改变产速；资源不会出现负数或非数值。

## 阶段 4：物品、品相与库存

1. 实现物品实例、八种品相、随机词条和装备槽。
2. 建立约 80 种物品的完整配置，覆盖武器、防具、法宝、功法、丹药、药材、矿材和秘境奇物。
3. 实现掉落生成、装备属性汇总、锁定、分解、筛选和排序。
4. 实现强化和重铸，并确保锁定物品不会被分解。
5. 为每个品相定义边框、印章纹样、光效强度和音效级别。

验收：批量生成物品符合权重；同名物品的不同品相与词条能改变战力；分解产物正确。

## 阶段 5：存档与离线收益

1. 实现版本化 JSON 存档、设置文件和自动备份。
2. 在关键操作后保存，并每 10 秒自动保存。
3. 实现离线时间差计算，限制为 0–8 小时。
4. 实现损坏存档保留、备份恢复和安全新档。
5. 实现存档导出、导入和重置确认。

验收：关闭后重新启动可恢复完整状态；修改系统时间为过去不会产生收益；超长离线只结算 8 小时。

## 阶段 6：掌门案牍界面与天青水墨主题

1. 建立全局 Godot Theme：天青、深青、宣纸白、少量鎏金和八种品相色。
2. 完成顶部资源栏、左侧弟子排班、右侧生产与任务、底部导航。
3. 完成总览、排班、库存、功法、远征五个主界面。
4. 加入键盘焦点、悬停提示、按钮反馈、确认弹窗和通知队列。
5. 使用容器与锚点适配 1280×720 至 1920×1080。

验收：所有首要操作在两次点击内完成；两种目标分辨率下无重叠、裁切或不可读文字。

## 阶段 7：炼丹、远征与境界突破

1. 完成六个炼丹配方、队列、弟子加成和高品结果概率。
2. 完成八个秘境、二十种事件、1–3 人编队与自动结算。
3. 完成远征时间轴、战利品结算与失败保护。
4. 完成十境界的突破条件、成功率、调息和解锁内容。
5. 完成渡劫与真仙的可跳过全屏演出。

验收：炼丹、远征、装备和突破形成资源闭环；玩家能够从炼气推进至真仙，配置不会在后期断档。

## 阶段 8：原创美术、动效与音频

1. 使用 imagegen 生成原创的天青水墨宗门背景与三名弟子立绘，保存到项目资产目录。
2. 检查生成图的角色一致性、构图、透明边缘和可读性；必要时只做一次定向修正。
3. 制作代码原生的面板纹理、品相边框、图标底板和粒子效果。
4. 加入墨滴、印章、升级、稀有掉落与雷劫动画。
5. 加入可商用或原创的环境音与界面音效；若无可靠来源，以简洁的程序音效代替，不引入来源不明素材。

验收：所有外部资产均有明确来源记录；在目标分辨率下图像无拉伸、文字与背景对比充足。

## 阶段 9：平衡、试玩与 Windows 导出

1. 调整前 30 分钟体验，使玩家能完成排班、升级、炼丹、远征和首次突破。
2. 模拟 8 小时离线、长时间在线、库存接近上限和十境界通关。
3. 检查存档兼容、数值溢出、窗口缩放、静音和退出流程。
4. 修复阻断级和高影响问题，记录未进入首版的扩展项。
5. 导出 Windows x64 正式构建到 `outputs/taixu-sect/`，包含 `.exe`、资源包与简短运行说明。

验收：正式构建在未安装 Godot 的 Windows 环境中可启动；关键流程无阻断错误；交付目录可直接复制运行。

## 验证命令与证据

- 使用 Godot 无界面模式运行配置与核心逻辑测试。
- 使用 Godot 命令行启动主场景并收集脚本错误。
- 对 1280×720 和 1920×1080 分别截取主界面、库存与远征画面。
- 对正式导出目录执行独立启动检查。
- 最终记录构建路径、Godot 版本、测试结果、已知限制和美术提示词。

## 计划边界

首版不实现账号、云存档、付费、联网、多人、排行榜、创意工坊或移动端导出。后续扩展必须建立在现有配置和存档版本迁移机制之上。
